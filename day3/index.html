Foundations · every machine has an address

An IP address is a street address for a machine

IP address IPv4

A unique number identifying a machine on a network. The common form is four numbers, each 0–255.

Example: 47.253.1.100 — that could be yesterday's server.

Subnet neighborhood

A group of addresses that can talk to each other directly, without leaving the neighborhood. Your server's vSwitch from Day 1 is a subnet.

Network vs host

Every address splits into two parts: the network part (which neighborhood) and the host part (which house in it).

Everything else today — CIDR, RFC1918, even DNS — is built on top of this one split: network part, then host part.
Presenter: land "network part, host part" as a phrase they'll hear again in five minutes. Don't rush this — it is the substrate the whole session rests on.

Foundations · writing a range of addresses

CIDR: one slash-number names a whole block

CIDR notation describes a block of addresses with a slash number, like 192.168.0.0/24. The number after the / says how many bits are fixed as the network part. The rest are free for hosts. An IPv4 address is 32 bits total.

CIDRFixed bitsFree bitsAddresses
/323201 (a single host)
/24248256
/16161665,536
/882416,777,216
/0032the entire internet

Rule of thumb

Free host bits = 32 − /number. Addresses = 2^(free bits). Bigger /number = smaller, more specific block.

Reading a block

192.168.0.0/24 means "addresses 192.168.0.0 through 192.168.0.255" — the first three numbers locked, the last free.

Presenter: work through /24 out loud before the widget — "24 fixed, 8 free, 2^8=256" — so the slider on the next slide is confirming a calculation they already did, not introducing a new one.

CIDR · drag the slash, watch the block resize

Bigger /number, smaller block — feel it, don't just memorize it

Presenter: start at /24, then drag to /8 and /32 and pause at each — read the address count and the network→last range out loud. Then watch the three probe IPs flip between inside/outside as you drag; that flip is exactly what Noura's drills ask them to compute on paper.

Foundations · addresses that never leave the building

RFC1918: three ranges reserved for private networks

10.0.0.0/8 (10.x.x.x) 172.16.0.0/12 (172.16.x.x – 172.31.x.x) 192.168.0.0/16 (192.168.x.x)

Exactly three ranges

Memorize them — you will see them everywhere. Your VPC's CIDR block comes from one of these.

Private ≠ reachable

Your server has a private IP from one of these ranges (used inside the VPC) and the public EIP you attached on Day 1 (used from the internet). That is why the EIP was needed — the private address alone can't be reached from outside.

Presenter: point straight back at Day 1's EIP step. This is the "why" for a decision they made on faith three days ago.

Foundations · names instead of numbers

DNS is the internet's phone book

DNS translator

Nobody remembers 47.253.1.100. DNS (Domain Name System) translates human names into IP addresses.

badge.example.com —DNS lookup→ 47.253.1.100

sslip.io the trick you already used

<ip-with-dashes>.sslip.io answers any lookup with the IP baked into the name itself. That is how your badge got a real hostname — and HTTPS — with zero DNS setup on Day 2.

Watch a lookup happen

Run this from any terminal — no server needed:

nslookup github.com
dig +short github.com
The DNS record on your badge's certificate is Caddy — from Day 2 — proving to the world it owns that name before it hands you a padlock.
Presenter: run dig +short github.com live on the projector — the raw IP printing out is the whole concept in one command.

Task · Noura's CIDR drills

Fast recall — work these from the rule of thumb, no tools

1. How many addresses are in 10.0.0.0/16 ? → ______ 2. How many addresses are in 172.20.5.0/24 ? → ______ 3. Is 192.168.1.50 inside the block 192.168.1.0/24 ? (yes/no) → ______ 4. Is 10.5.0.1 a private (RFC1918) address? (yes/no) → ______ 5. Which is a bigger block: /20 or /24 ? → ______
Hint: addresses in a block = 2^(32 − /number). For "is this IP inside?", check whether the fixed network part matches.
Presenter: work these live, cold-call the room. Answers: (1) 2^16 = 65,536. (2) 2^8 = 256. (3) yes — same first three octets. (4) yes — falls in 10.0.0.0/8. (5) /20 is bigger — fewer fixed bits, 2^12=4,096 addresses vs 2^8=256 for /24.

Foundations · the network you already have, named properly

VPC, then vSwitch — the same nesting as CIDR

VPC Virtual Private Cloud

Your own private, walled-off network inside Alibaba's cloud. You pick its address range — a CIDR block, like 192.168.0.0/16. Nothing outside gets in unless you allow it.

vSwitch subnet

A subnet inside the VPC — a smaller CIDR slice that lives in one Availability Zone. Your server plugs into a vSwitch.

VPC 192.168.0.0/16 (your whole private network) └── vSwitch 192.168.1.0/24 (a subnet in Zone A) ← your ECS instance lives here
This is the exact nesting from the CIDR slider last session — a bigger block containing a smaller, more specific one.
Presenter: this is the layout they inspected on Day 1 without a name for it. Say that explicitly — "the default VPC and vSwitch your instance launched into, this is what those were."

Foundations · the firewall around your server

A security group is a list of rules: port, protocol, source

A security group is a firewall wrapped around your instance — a list of rules saying which traffic is allowed in (inbound) and out (outbound). By default, almost everything inbound is blocked, which is why a brand-new server is unreachable until you open something.

This is the thing you opened on Day 2. The inbound rules for 80 and 443 were exactly this.
Rule partExampleMeaning
Port443Which "door" — see ports, next slide
ProtocolTCPThe kind of traffic
Source0.0.0.0/0Who's allowed — 0.0.0.0/0 = anyone (that /0 from last session!)
Presenter: tie 0.0.0.0/0 straight back to the CIDR slider — same notation, same meaning, "the entire internet."

Security groups · send traffic, watch the wall decide

Same port, different rule — and everything changes

Presenter: it starts on Turki's exact broken rules. Send to :22 first — it passes. Then send to :443 and let the room watch it die at the wall with no rule at all. Then toggle :443 open and resend. Finally toggle a rule to "VPC only" and send from "the internet" to show port-open ≠ reachable.

Foundations · the numbered doors on your server

Ports let one machine run many services at once

PortService
22SSH (how you log in)
80HTTP (plain web)
443HTTPS (secure web — your badge!)
Remember docker run -p 80:80 from Day 2? That was port forwarding — a port on the host connected to a port inside the container. Traffic arriving at the server's door 443 gets forwarded to Caddy inside the container. The security-group rule is what let it arrive at all.
Presenter: land the two-layer picture — security group decides if traffic reaches the server's door at all; -p from Day 2 decides which container door it goes through next.

Foundations · as apps grow past one server (concept only)

Three ideas you should recognize, not configure this week

Load balancer

Sits in front of many servers and spreads incoming traffic across them, so no single one is overwhelmed.

Proxy

A middle-man that forwards requests. Caddy is acting as one — forwarding web requests to your files.

CDN Content Delivery Network

Copies of your content cached in cities worldwide, so users load it from somewhere nearby and fast.

💡 On Alibaba these map to SLB (load balancer) and CDN — good to know the names, not something you'll set up this week.
Presenter: keep this to under two minutes — names to recognize, not a mechanism to teach. Resist the urge to demo SLB.
